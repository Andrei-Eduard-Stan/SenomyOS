# Control Centre

| Contract | Specification |
| --- | --- |
| Opens | Rail system controls and `show-control SECTION` deep links |
| Geometry | Bottom-right; about 900–960 x 740–780 on 1920x1080, capped to the work area |
| Frame | Large |
| Motif | controls; local power/junction marks only |
| Routes | Overview, Network, Audio, Power, Calendar, Input, Devices, Applications, Appearance, Settings |

## Composition

Use one stable operational switchboard: shared header, persistent route spine, route-specific instrument stage, and guarded action dock. On narrow/portrait layouts, replace the vertical spine with an approved horizontal strip or drawer.

## Route character

- Overview: connected operational spine.
- Network: route topology and AP ledger.
- Audio: duplex channel bus.
- Power: paired battery cells and charge-flow thread.
- Calendar: calendar field and chronometer.
- Input: capability matrix/device tree.
- Devices: capability bus and endpoint ledger.
- Applications: lifecycle ledger.
- Appearance: live specimen and token controls.
- Settings: shell manifest and maintenance dock.

## Interaction and safety

Make the primary window keyboard-focusable by an approved focus model. Keep all current confirmation, polkit, safe handoff, status, failure, and capability-unavailable behavior. Read-only facts must not look like buttons.

## Acceptance

All ten routes fit or scroll with visible affordance; text is readable; action scope is explicit; no route is a stack of indistinguishable cards; the frame never obscures a scrollbar, control, or status.
