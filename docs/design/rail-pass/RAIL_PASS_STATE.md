# SenomyOS Obsidian Rail Pass State

Last updated: 2026-08-26 06:03 Europe/London

## Scope

This pass changes only the persistent SenomyOS Obsidian Rail. It may inspect
shared appearance, primary-surface routing, collectors, and deployment logic,
but it must not restyle Control Centre, Performance, Insights, Command Lens,
Thunar, SDDM, Hyprlock, or the companion.

The live implementation is the functional and data source of truth. The
selected reference is the visual source of truth:

`assets/mockups/ChatGPT Image Aug 26, 2026, 05_32_43 AM.png`

## Locked visual rules

- Transparent obsidian structure with luminous white/silver information.
- Violet is restricted to active workspace, focus, selected controls, and the
  Senomy identity trace.
- Green, amber, and red remain semantic success, warning, and critical colors.
- Workspaces are unboxed, show stable numbers, and may render multiple real
  application icons beneath each number.
- Identity, telemetry, system controls, calendar/clock/notifications, and
  power remain distinct functional regions.
- Power is separated at the far right as a safety affordance.
- Hierarchy comes from space, type, line, and luminance before containers.
- Existing handlers, collectors, confirmation boundaries, and the
  one-primary-surface coordinator remain authoritative.

## Rail architecture

```text
main-bar Eww window
  -> workspace-indicator
       -> workspace_state from workspaces.service/scripts/workspaces.sh
       -> workspace-action.sh for validated switching
  -> senomy-status
       -> companion-state.sh (avatar)
       -> surface-state.sh (Insights dialogue)
  -> system-summary
       -> rail_system_status
       -> surface-state.sh (Performance)
  -> Applications / Audio / Network / Battery controls
       -> existing flyout and Control Centre routes
  -> Clock / Notifications
       -> existing Calendar and Insights routes
  -> isolated Power entry
       -> existing confirmed Control Centre Power route
```

Only `active_surface = none | control | performance | insights` owns a primary
surface. The Rail pass must not add independent popup flags.

## Intentional P3 differences and known limits

- The Rail remains bottom-anchored with a small safe inset instead of copying
  the mock's large decorative gap below it; the exclusive work area and
  existing panel placement remain functional truth.
- Workspace applications, telemetry, battery, time, notification count, and
  dialogue are live data rather than copied illustrative values.
- The repository's approved Senomy avatar is used instead of extracting or
  approximating the mock artwork.
- The companion avatar and Insights dialogue retain separate interaction
  targets and a fine internal divider, as required by the accepted product
  model.
- `eww logs` currently targets a missing cache file even though guarded reload,
  daemon/process census, active windows, and Hyprland configuration checks are
  healthy. This pre-existing Eww log-path limitation was not worked around by
  adding a second daemon or logger.
