## Visual Rules

- The approved August 28 frame sheet is the visual source of truth.
- Modern terminal structure comes first; restrained cathedral-machine detail
  comes second.
- White/ivory/silver owns 65–75% of visible structure, steel owns 20–30%, and
  semantic violet stays at or below 5%.
- Compose frames from fixed optical corners, neutral extensible edges, fixed
  anchored motifs, and optional fixed crests. Never stretch a complete frame,
  corner, node, finial, junction, or crest.
- Use rounded silhouettes, transparent interiors, canonical safe zones, and
  CSS-controlled state luminance. Decorative layers may not intercept input.

## Discovered Appearance Architecture

Initial inspection confirms a central appearance layer already exists:

`appearance/tokens.json`
→ `scripts/generate-appearance.py`
→ generated toolkit and shared assets
→ deployment manifests/scripts where external installation is required
→ guarded Eww reload for the live shell.

The current Rail already consumes token-generated modular compact SVGs from
`appearance/shared/frames/` through `appearance/shell/eww.scss`. The new system
will extend that pipeline rather than create a parallel theme source.

The live repository is itself Eww's deployment target. Root `eww.scss` is a
compatibility import into `appearance/shell/eww.scss`; `eww.yuck` includes the
modular widget/window sources. The supported shell apply path is
`scripts/senomy-appearance.sh apply shell`, which rebuilds projections, runs
the validators, requires the exact interactive confirmation `RELOAD SHELL`,
then calls the state-preserving Eww reload coordinator.

Rofi—not Wofi—is the current launcher implementation. GTK/Thunar, Rofi,
Hyprlock, SDDM, recovery, and boot files deploy through transactional manifests
with receipts and backups; none is a Rail deployment target. No appearance
symlinks or separate appearance watcher were found. Eww's own source watching
exists at runtime, so permanent edits stay in the canonical `appearance/`
source and generated outputs are rebuilt atomically.

The tracked/live Hyprland `.conf` pair and tracked/deployed Lua pair are
byte-identical. No Hyprland change is required for this frame pass.

## Frame Tiers

- **Compact:** 44px optical Rail frames; deliberately simplified.
- **Standard:** medium panels/cards; richer corners and junctions.
- **Large:** large windows/overlays; deeper architectural rhythm and optional
  crests without scaling Compact geometry.

Canonical metrics now live in
`appearance/shared/frames/frame-system.json`:

- **Compact:** 16x16 fixed corners, 32x6 horizontal neutral edges, 6x24
  vertical neutral edges, 9/7px horizontal/vertical safe insets, and a 44px
  optical Rail height.
- **Standard:** 32x32 fixed corners, 48x9 horizontal neutral edges, 9x48
  vertical neutral edges, and 16/14px safe insets.
- **Large:** 48x48 fixed corners, 64x12 horizontal neutral edges, 12x64
  vertical neutral edges, and 24/22px safe insets.

The three corner families have separately authored geometry; they are not one
scaled drawing.
