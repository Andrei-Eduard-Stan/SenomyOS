# Conditional automatic keyboard — 2026-10-10

Default Auto mode opens the owned keyboard for compositor-reported active text input only when no usable physical keyboard is detected. Enabled, allowed, non-virtual libinput keyboards are checked for A, Z and Space capabilities; power/media-button devices are excluded. Unknown non-libinput physical backends conservatively block automatic opening. Virtual keyboards never count as physical. A disabled keyboard is treated as unavailable; automatic tablet posture detection is not implemented.

The existing exact-version Caps/fitting component exports only focus/device/session booleans and a focus generation. New text-input-v3 enable/disable listeners capture rapid transitions that a frame tick alone misses. The native provider can attach an optional input-method observer when no input method exists, remain hidden until requested by policy, and release its own connection when automatic mode is disabled or physical typing becomes available. An existing IME retains its seat slot; the observer never grabs keys and its surrounding-text callback discards data. No typed text is logged or placed in shell state.

Manual Show pins visibility, manual Hide suppresses the current editing session, and confirmed Stop pauses automatic startup for this session. Mode is stored atomically as `auto`/`manual` in the user configuration directory (0600). Unknown focus or component failure falls back to manual control. Exact Hyprland SDK/version/hash checks remain required; this does not establish distribution packaging or universal app/device support.

Validation: pinned native binary and exact-version plugin rebuilt; 9 capability, 13 provider, 4 Caps-helper and 3 automatic-helper tests pass; 19 controller and 12 automatic-policy Qt cases pass, with existing Qt diagnostics. In a private compositor the real managed provider follows text-input-v3 enable/disable, reuses its PID, respects manual dismissal including rapid disable/enable, pauses/resumes when a physical backend keyboard is enabled/disabled, persists Manual mode, allows manual show and preserves manual visibility on blur. A separate existing-IME fixture proves no needless pre-arm, automatic visibility from its text-input signals, and preservation of the existing IME after owned OSK exit.

Toolkit limitation: an initial Qt click fixture inconsistently kept its text-input session enabled after internal item focus changed, and did not provide dependable per-field acceptance. The final integration fixture uses a minimal actual Wayland text-input-v3 client with explicit enable/disable requests; it does not prove Firefox/Electron/XWayland compatibility, physical touch, phone/ARM, lock-screen typing, or real USB/Bluetooth hotplug. Apps that do not report text focus need manual controls. Field transitions on already-existing IME-backed v3 objects at plugin load rely on native observation/observed state; rapid transitions before new listener registration are not universally covered.

Live: Quickshell PID 1467 loaded this stage, Rail remains visible, Hyprland configerrors is empty, and the compositor reports physicalKeyboard=true on the reference laptop. Auto therefore remains paused; no text or pointer input was injected into user applications. Previous installed binaries/receipt are retained in the private development stage. Source consumer changes are checkpointed against the untracked InputSettings baseline; unrelated dirty/untracked source remains preserved.

Fixtures are audit artifacts from the private stage, not standalone packaging or live-session launchers. Their paths are deliberately confined to that stage.
